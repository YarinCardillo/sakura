# Quota enforcement hooks

W2 of the quota service plan.

The hooks use Python's standard library and the service's `POST /advise` and
`GET /status` JSON contract. Tests use a stub advisor and an isolated loopback
HTTP server. There is no production stub that silently authorizes work.

## Install after review

From a stable checkout, run:

```sh
bin/sakura quota-hooks install
```

This explicitly merges command hooks into every existing Claude profile found
through the account registry, structural discovery, the standard and alternate
Claude directories, `CLAUDE_CONFIG_DIR`, and Orca's managed profiles. Resolved
paths are deduplicated. No credential file is opened. Existing settings and
unrelated hooks are preserved. Writes are atomic per profile and preserve its
settings file permissions. Rerunning installation updates the owned hooks and
safely resumes after a partial failure. It does not modify the existing Git or
repository guard hooks.

For an isolated smoke test or a different service port:

```sh
bin/sakura quota-hooks install --profile /tmp/test-claude-profile --advisor-url http://127.0.0.1:8800
```

The directory must already exist. Each installed command binds the profile
path and advisor URL explicitly. Its executable path points at this checkout,
so keep that checkout available. No profiles are installed merely by importing
modules or running tests.

## Behavior

- `PreToolUse`, matcher `^(Agent|Task|Bash)$`: ask the advisor for each Agent/Task
  launch. Return the full original tool input with the advised `model`. Deny
  `deny`/`wait`, or a route requiring a different account/provider, with the
  returned reason and retry time. The caller must relaunch that route explicitly.
- `SessionStart`: inject the current routing advice. Show a warning when the
  current profile's weekly reading or next-round forecast reaches the threshold
  (95% by default, configurable with `SAKURA_QUOTA_THRESHOLD_PCT`). Stale quota
  warnings are marked. Accounts are matched by resolved `config_dir` and the
  optional `aliases` returned by the service for deduplicated profiles.
- `UserPromptSubmit`: block only `deny`, using the documented top-level
  `decision: block`. Other verdicts become context for the session.
- Direct `codex exec` calls in Bash: check the requested `-m`/`--model` and
  `CODEX_HOME` against the advised route. Deny missing/mismatched models,
  mismatched accounts/providers and `deny`/`wait`. Simple `cd`, `-C`/`--cd`,
  exports, assignments and unsets are applied to each launch before requesting
  advice. Dynamic account/repository paths require an explicit relaunch with
  absolute literal paths. Put model options before the prompt. Never rewrite shell code.
  This is a command hook check, not a shell sandbox: code generated by scripts,
  shell functions and nested interpreters is outside its inspection boundary.

Unclassified launches use role `builder` and task class `integration`.
Agent types containing Explore, Plan, review or evaluat map to the corresponding
contract role. For an explicitly configured runner, use `--role` and
`--task-class` to supply the task's known classification. Prompt text and
transcripts are never sent to the advisor.

Service errors, timeouts and malformed responses allow work and log a warning
to stderr. Requests use only `127.0.0.1`, ignore HTTP proxy settings, never follow
redirects, time out after one second and cap responses at one MiB. The hook
runner exits zero and emits only valid decision JSON on stdout. Advice is
stateless: retries and repeated hook execution do not consume or reserve quota.
A failed `/status` request still preserves available session advice.

## Official Claude Code contract verified

Checked on 2026-11-02 against the official
[hooks reference](https://code.claude.com/docs/en/hooks#pretooluse-decision-control):
`updatedInput` replaces the entire tool input. The hook must preserve unchanged
fields, including prompt and subagent type. The documented
[Agent input](https://code.claude.com/docs/en/hooks#agent) includes optional
`model` to override the default. This implementation omits `permissionDecision`
when rewriting, preserving normal permission processing. Denials use
`hookSpecificOutput.permissionDecision: deny`. `Task` is included for legacy
callers; the current reference names the tool `Agent`.

The Agent input documentation does not expose account selection or effort.
The hook enforces the model, reports effort as context and denies routes that
need another process. Real Claude runtime verification and the coordinator's
profile installation remain review/cutover steps; tests never launch Claude.
